# The note-to-rule loop

This is how the system gets better with use. Every piece of feedback becomes a permanent rule, so the same note is never needed twice.

## The loop

1. **Hand over the material.** Brief and footage. No editing app needed.
2. **The agent edits and renders a draft.**
3. **You watch it and say what is wrong in plain words.** "I can't read that caption." "That shot doesn't move." "Those sound effects sound cheap."
4. **The agent fixes the draft AND writes the fix down** as a rule, a check, or a script change. Ask for it explicitly: "Fix it, then add this to the knowledge base so it never happens again."
5. **The next project starts from the improved base.**

## Where each kind of note goes

| A tool command | `04_SOFTWARE_MANUALS/...` |
| A final check that was missed | `02_VIDEO_EDITING/editing-techniques/qc-checklist.md` |
| Anything else | Write in `lessons-log.md`, promote later |

## Rule-writing standard

A good rule has: **what to do**, **why**, and **how to check**. "Captions never cover the mouth" is weak. "Captions never cover the mouth or chin, especially in the first second; check the first 2.5 s frame by frame" is strong.

## Measurable beats vague

If a note can become a script (contrast check, loudness check, lip-sync frame compare, variety audit), make the script. A check that runs every time is worth ten reminders.

## Retire old rules

If a rule no longer holds, mark it retired in the log with the reason. Do not leave contradictory rules in the base.

## Weekly habit (10 minutes)

1. Read the week's notes.
2. Promote any that repeated.
3. Rebuild `knowledge-index.csv`.
4. Commit with a message that names the rules changed.
